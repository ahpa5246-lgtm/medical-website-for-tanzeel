# حالة تنفيذ ميدكونكت

## ما اكتمل في واجهة المرحلة الأولى

- واجهة عربية أولًا واتجاه RTL متجاوب للهاتف والكمبيوتر.
- صفحة رئيسية بهوية «مسار الرعاية» توضّح السؤال والتحقق والاستجابة.
- نموذج استشارة مع تحقق من الحقول وكشف أولي لعبارات الطوارئ.
- قائمة الاستشارات ومثال لخيط المتابعة والتقييم والرأي الثاني.
- دليل أطباء، صفحة ملف طبيب، وشارات تحقق واضحة.
- التسجيل والدخول واستعادة الوصول واختيار دور المستخدم.
- نموذج طلب تحقق مهني للطبيب مع توضيح دورة المراجعة.
- قائمة مقالات، صفحة مقال، ومساحة كتابة وإرسال للمراجعة الطبية.
- صفحات التنويه الطبي والخصوصية وشروط الاستخدام.
- صفحات صريحة للمرحلة الثانية بدل عرض الدورات والمكتبة كخدمات جاهزة.
- تنبيه معاينة يمنع المستخدم من الاعتقاد بأن البيانات تُحفظ حاليًا.

## ما لم يُنفذ عمدًا قبل الإنتاج

المشروع الحالي React/Vite واجهة فقط. لا توجد قاعدة بيانات أو حسابات حقيقية أو تخزين ملفات أو صلاحيات خادم. لذلك لا تُحفظ النماذج ولا تُرسل رسائل أو وثائق.

يلزم قبل أي إطلاق حقيقي:

1. اعتماد قرار معماري للانتقال إلى Next.js كما يوصي المستند، أو الموافقة صراحة على إبقاء Vite مع خدمة خلفية منفصلة.
2. ربط Supabase أو بديل يدعم Postgres وAuth وStorage وسياسات Row-Level Security.
3. بناء صلاحيات المرضى والأطباء والمراجعين والإدارة واختبار حدود الوصول آليًا.
4. تفعيل التحقق عبر الهاتف والبريد و2FA للحسابات ذات الصلاحيات.
5. تخزين المستندات والمرفقات في حاويات خاصة وروابط موقّتة مع فحص النوع والحجم.
6. إضافة تحديد المعدل، سجل التدقيق، التصدير والحذف، والمراقبة والنسخ الاحتياطي.
7. مراجعة قانونية محلية للتنويه والخصوصية والاستشارات عن بعد قبل الإطلاق.

## قرارات عمل لازمة

- الاسم والعلامة النهائية؛ «ميدكونكت» اسم مؤقت.
- مسؤول المراجعة الطبية ووقت المراجعة المتوقع.
- اعتماد قائمة التخصصات والتصنيفات.
- هل تبقى الاستشارات مجانية بعد الإطلاق.

## التحقق التقني

- `pnpm exec tsc --noEmit`
- `pnpm build`
- فحص استجابة المسارات الأساسية محليًا؛ جميعها أعادت HTTP 200.
